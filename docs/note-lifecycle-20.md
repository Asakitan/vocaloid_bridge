## Identity-preserving operation baselines

Four additional cases construct two AI tracks containing two notes apiece and distinct nested pitch markers. They exercise track update, track reorder, part update, and same-track part move separately, checking markers, undo/redo, source preservation and saved reopen. Old-host receipt `artifacts/feature-acceptance-e17a8ae419b4/summary.json` records the expected four guard rejections and successful cleanup; the rebuilt host passed the four cases in `artifacts/feature-acceptance-5b8f6372f11d/summary.json`. Deleting tracked notes, parts, or tracks additionally requires a target-bound deletion hook before staged validation; relaxing the current guard alone would leave a disappeared owner in the tracked map.

Static review found that a `DidRemove` notification can evict a subtree from `Live` even for a move. Before commit, the four operations independently enumerate native notes and require each pre-edit pitch-bearing owner and its full point set to remain present. `ArchiveRefreshParents` restores pre-edit entries by native identity for these operations and updates parents; history uses strict parent checks. Delete and split/join guards remain unchanged.

A separate cross-AI-track `part.move` case checks distinct source/target pitch markers, both track contents, undo/redo and reopen; it includes invalid destination and indistinguishable-position rejection checks. The old host rejected the positive move at the extension guard, with cleanup passing in `artifacts/feature-acceptance-20cc5c8a6e51/summary.json`. A plain native overlap probe in `artifacts/feature-acceptance-830932006da1/summary.json` showed that the native engine accepts overlapping parts, so the bridge now rejects an indistinguishable part signature before moving or duplicating while pitch item extensions are tracked. The first rebuilt-host case failed on a test assumption that empty tracks always serialize `parts`; after correcting the assertion, it passed with the ordinary AI automation case and cleanup in `artifacts/feature-acceptance-17fec2e1ace1/summary.json`. The original failure remains in `artifacts/feature-acceptance-5b8f6372f11d/summary.json`.
