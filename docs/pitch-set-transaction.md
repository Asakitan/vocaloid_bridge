# Direct-pitch transaction probe

The private desktop probe `tools/check_pitch_set_transactions.py` accepts a synthetic `preservation.note_pitch_transitions` replace fixture. It records each native staged point set, commit or injected-error rollback, undo/redo and saved-project reopening. The injected failure is deliberately generated by the probe after a successful native mutation; it is not a naturally observed `SetDirectPitch` failure.

Observed on a 960-tick note with baseline points at 100 and 400: replacing with points at 0 and 959 produced exactly those points while staged and after commit; overwriting 100 preserved the point at 400. Undo restored the baseline, redo restored the edited points, and reopen matched redo. The injected staged failure rolled back to baseline and reopening matched baseline. No automatically generated extra points were observed in these cases. A raw native tick of 100000 was accepted in a separate exploratory run; the bridge rejects out-of-range ticks before mutation.

`pitch.set` now checks every requested anchor while staged and again after
commit. A staged mismatch uses the existing rollback path. The probe's injected
failure is not a reproduced natural mismatch. Generated points from other
operations remain outside this probe; the restricted archive-extension set/clear
path has separate focused MCP evidence in
`artifacts/feature-acceptance-1de6c1d0abc4/summary.json`.
